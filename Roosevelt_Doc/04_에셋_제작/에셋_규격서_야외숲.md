# 에셋 규격서: 야외 숲 환경

작성 2026-09-12. Unity 6 URP에서 연구소 외곽의 숲을 조립하기 위한 환경·프랍 규격이다. 실내 모듈은 `에셋_규격서_지하연구소.md`를 따른다.

## 1. 목표와 범위
- 용도: 1인칭 내러티브 호러의 야외 연결 구간. 넓은 오픈월드가 아니라 연구소 외벽·숲길·외곽 시설을 잇는 제한된 탐험 공간이다.
- 시각 목표: 탁한 자연 속에 연구소의 인공 구조물이 침범한 느낌. 멀리까지 실제 숲을 만들기보다 안개와 원경으로 숲의 깊이를 암시한다.
- 첫 구현 단위: `Forest_Test` 씬 하나. 걷기 가능한 영역은 최대 128×128m로 시작한다.

## 2. 씬 구성

```text
Forest_Test
 ├─ Terrain_Playable       실제 이동 가능한 지형
 ├─ Path                   흙길·자갈길·배수로
 ├─ Trees_Near             수동 배치 나무·뿌리·바위
 ├─ Trees_Mid              Terrain 배치 나무·수풀
 ├─ Forest_Backdrop        원경 나무 벽·산 능선·안개 카드
 ├─ Facility_Exterior      외벽·펜스·서비스 출입구·설비
 ├─ Lighting               태양/달 Directional Light, 제한된 시설등
 ├─ Atmosphere             Skybox, Fog, URP Volume
 └─ Gameplay               충돌, 상호작용, 출입 제한
```

플레이어가 보는 숲은 아래 세 거리 계층으로 나눈다.

| 거리 | 구성 | 배치 방식 |
|---|---|---|
| 0~12m | 큰 나무, 뿌리, 바위, 쓰러진 줄기, 시설물 | 프리팹 수동 배치. 충돌·상호작용 가능 |
| 12~45m | 반복 나무, 수풀, 풀 군집 | Terrain Paint Trees/Details 또는 인스턴싱 |
| 45m 이상 | 낮은 폴리 나무 실루엣, 산, 안개 | `Forest_Backdrop` 전용 메쉬·카드. 충돌 없음 |

## 3. Terrain

| 항목 | 첫 테스트 기준 | 메모 |
|---|---:|---|
| Terrain 크기 | 128×128×24m | 가로×세로×최대 높이. 확장 시 같은 크기 타일을 이어 붙인다 |
| Heightmap Resolution | 257 | 낮은 해상도의 완만한 지형을 유지. 가파른 절벽·길 경계는 별도 메쉬를 쓴다 |
| Alphamap Resolution | 512 | 지면 레이어 페인팅용 |
| Detail Resolution | 512 | 풀·작은 수풀만 사용. 처음에는 밀도를 낮게 시작한다 |
| 플레이 영역 | Terrain 가장자리에서 최소 8m 안쪽 | 바깥 8m는 경사, 수풀, 나무 벽, 안개로 경계를 숨긴다 |
| 동선 | 폭 2~3m | 길은 완전히 직선으로 두지 않고 10~20m마다 굴곡 또는 시야 차단물을 둔다 |

- 지형은 평평한 판처럼 두지 않는다. 숲길과 주변 바닥에는 8~15m 간격의 완만한 기복을 주며, 한 번의 오르내림 높이 차는 0.3~0.6m를 기준으로 한다.
- 실제 이동 경로의 횡경사는 8° 이하, 진행 방향의 경사는 12° 이하로 시작한다. 길 한가운데에 작은 노이즈를 많이 넣지 말고, 낮은 둔덕·얕은 물웅덩이·나무 뿌리 주변의 움푹한 바닥처럼 큰 덩어리로 높낮이를 만든다.
- 지형은 낮은 둔덕 하나와 완만한 저지대 정도로 구성한다. 플레이어가 멀리 볼 수 있는 높은 능선은 첫 씬에서 만들지 않는다.
- Terrain의 구멍 기능은 건물 기초, 배수구, 지하 출입구처럼 실제로 지형을 뚫어야 하는 경우에만 쓴다.
- 발이 닿는 땅에는 TerrainCollider를 쓴다. 길·배수로·절벽을 별도 메쉬로 덮었다면 메쉬 충돌은 필요한 부분에만 붙인다.

### 3.1 Terrain Layer

| 레이어 | 이름 | 사용 위치 | 색·질감 |
|---|---|---|---|
| 기본 흙 | `TL_Forest_Dirt` | 숲 바닥 대부분 | 어두운 청록·갈색 파생, 넓고 흐린 얼룩 |
| 죽은 풀 | `TL_Forest_DeadGrass` | 나무 사이·길 가장자리 | 탁한 베이지, 반복 대비 약하게 |
| 자갈 | `TL_Forest_Gravel` | 시설 진입로·배수로 주변 | #f4e1a4 계열의 어두운 회색 파생 |
| 젖은 흙 | `TL_Forest_WetSoil` | 저지대·배수구·설비 주변 | 더 어둡고 채도 낮은 흙, 물 고임은 별도 데칼/메쉬 |

- 텍스처는 `T_Forest_Terrain_*` 접두사를 쓰며, 기본 해상도는 512×512이다.
- 바닥 무늬가 일정한 간격으로 반복되어 보이면 Terrain Layer 타일 크기를 키우고, 풀·낙엽·자갈 프랍으로 반복을 끊는다.

## 4. 식생 에셋

### 4.1 1차 제작 목록

| 분류 | 이름 예시 | 기준 크기 | 삼각형 예산 | 용도 |
|---|---|---:|---:|---|
| 큰 나무 | `SM_Forest_Tree_DeadA` | 3×3×8m | 500 이하 | 기본 죽은 나무. 0~45m 거리에서 사용 |
| 큰 나무 | `SM_Forest_Tree_DeadB` | 4×4×11m | 650 이하 | 굽은 줄기·긴 가지. 길의 시야 차단용 |
| 기형 나무 | `SM_Forest_Tree_Twisted` | 4×4×7m | 700 이하 | 희고 얽힌 뿌리가 사람 형태를 연상하는 핵심 실루엣. 드물게 수동 배치 |
| 쓰러진 줄기 | `SM_Forest_Log_Fallen` | 1×6×1m | 250 이하 | 길 가장자리·경계. 넘을 수 없는 낮은 장애물 |

| 수풀 | `SM_Forest_Shrub_A/B` | 1~2m 폭 | 120 이하 | 길 가장자리·지형 경계. 충돌 없음 |
| 풀 군집 | `SM_Forest_Grass_01/02` | 0.5~1m 폭 | 40 이하 | Terrain Detail 또는 GPU 인스턴싱. 플레이어 가까이만 표시 |
| 바위 | `SM_Forest_Rock_S/M/L` | 0.5/1.5/3m 폭 | 80/180/350 이하 | 지형 경사·나무 밑동·길 경계 |
| 뿌리 군집 | `SM_Forest_RootCluster_A` | 2×2×1m | 250 이하 | 기형 나무 주변, 연구소 침식 표현 |
| 원경 나무 벽 | `SM_Forest_Backdrop_TreeWall_A` | 12×1×8m | 300 이하 | 45m 밖의 숲 실루엣. 여러 조각을 겹쳐 사용 |

### 4.2 식생 제작·배치 규칙
- 나무는 수피의 미세함보다 **줄기 방향, 가지의 갈림, 밑동 뿌리**로 읽혀야 한다. 잎이 무성한 건강한 숲은 1차 범위에서 만들지 않는다.
- 모든 큰 나무는 `DeadA`, `DeadB`처럼 2종 이상을 만들고, 높이 0.85~1.15배·Y 회전·색조를 약하게 바꿔 반복을 줄인다.
- 길의 양쪽 나무는 일정한 간격으로 줄 세우지 않는다. 한쪽을 더 빽빽하게 만들어 시선을 휘게 하거나, 열린 공간 뒤에 큰 실루엣 하나를 둔다.
- `Twisted`는 일반 나무보다 밝은 색을 쓰되, 한 화면에 1개 이하로 둔다. 가까이서 처음 발견될 때만 강하게 읽혀야 한다.
- 풀·수풀·원경 나무 벽에는 Collider를 붙이지 않는다. 플레이어가 막혀야 하는 곳은 큰 나무 줄기, 바위, 펜스, 경사처럼 눈에 보이는 물체로 막는다.

## 5. 시설 외곽과 지면 프랍

| 분류 | 에셋 | 용도 |
|---|---|---|
| 경계 | `SM_Forest_Fence_Chainlink_200x200`, `SM_Forest_Gate_Sliding` | 연구소 외곽선과 명확한 진행 제한 |
| 건축 | `SM_Forest_Wall_Concrete_400x350`, `SM_Forest_ServiceDoor` | 연구소 후면 외벽·비상 출입구 |
| 설비 | `SM_Forest_Generator`, `SM_Forest_ElectricalBox`, `SM_Forest_OutdoorPipe` | 야외 진행 목표와 시설의 존재감 |
| 조명 | `SM_Forest_LampPole`, `SM_Forest_WarningLight` | 길 유도. 실제 라이트 수는 제한 |
| 적치물 | `SM_Forest_Dumpster`, `SM_Forest_Pallet`, `SM_Forest_Crate_Plastic` | 서비스 공간의 현실감, 시야 차단 |
| 표식 | `SM_Forest_Sign_Warning`, `SM_Forest_CCTV` | 구역의 성격과 방향을 전달 |

- 실제 상호작용이 필요한 설비는 `PF_Forest_<종류>_<변형>` 프리팹으로 만들고, 배경용 정적 프랍과 분리한다.
- 연구소 외벽의 텍스처·색상은 실내 팔레트와 연결하되, 야외에서는 오염·습기·뿌리 침식을 더한다.

## 6. 하늘, 안개, 조명

| 요소 | 첫 테스트 기준 | 목적 |
|---|---|---|
| Skybox | 흐린 회녹색 또는 밤의 탁한 남색 | 멀리 보이는 하늘의 색을 고정 |
| Directional Light | 1개 | 달빛/흐린 낮의 큰 방향성. 나무 그림자를 만듦 |
| Ambient Light | 차가운 청록 계열, 낮은 강도 | 검은 그림자 속에서도 실루엣을 읽게 함 |
| Fog | Linear, 시작 25m / 끝 65m부터 시작 | 원경을 감추고 숲의 깊이를 과장 |
| URP Volume | Color Adjustments, Bloom, Vignette만 1차 적용 | 팔레트 통일. Bloom과 Vignette는 약하게 |
| 안개 카드 | 길 굴곡·저지대에 2~4장 | 전체 안개와 별개로 깊이와 움직임을 만듦 |

- 시설 경고등·가로등은 플레이어 진행에 필요한 장소에만 둔다. 첫 테스트에서는 동시에 보이는 실시간 Point Light를 4개 이하로 유지한다.
- 나무·바위·시설 외벽은 정적 오브젝트로 두고, 그림자 품질은 최종 아트 확정 전까지 낮게 시작한다. 풀과 원경 나무 벽은 그림자를 끈다.
- 하늘과 안개는 같은 계열 색을 쓰되 완전히 같게 하지 않는다. 하늘보다 안개를 조금 더 밝게 두면 멀리 있는 숲이 자연스럽게 사라진다.

## 7. LOD와 성능

| 자산 | LOD 0 | LOD 1 | LOD 2 / Cull |
|---|---|---|---|
| 큰 나무 | 0~12m, 전체 메시 | 12~28m, 가지 단순화 | 28~45m, 실루엣 메시. 45m 이후 원경으로 대체 |
| 바위·쓰러진 줄기 | 0~15m | 15~30m, 단순화 | 30m 이후 Cull |
| 수풀·풀 | 0~12m | 12~20m, 밀도 감소 | 20m 이후 Cull |
| 시설 프랍 | 0~25m | 25~45m, 단순화 | 45m 이후 Cull 또는 원경 메시 |

- 중거리 나무·수풀·풀은 가능한 한 동일 메시와 머티리얼을 공유해 인스턴싱한다.
- 원경 나무는 개별 나무를 끝없이 심지 않고 `TreeWall` 메쉬와 Fog로 대체한다.
- Collider는 `Trees_Near`, 상호작용 프랍, 반드시 막아야 하는 바위·펜스에만 둔다.
- 한 프레임에 보이는 복잡한 특수 나무(`Twisted`)는 2개 이하로 시작한다.

## 8. 이름과 출력 위치
- 메시: `SM_Forest_<종류>_<변형>_<가로x세로x높이cm>`
- 프리팹: `PF_Forest_<종류>_<변형>`
- 텍스처: `T_Forest_<대상>_<용도>`, 머티리얼: `M_Forest_<대상>`
- 예: `SM_Forest_Tree_DeadA_300x300x800`, `PF_Forest_Generator_Interact`, `T_Forest_Bark_Atlas`.

## 9. 검수
- 플레이어 높이에서 길을 따라 1인칭으로 걸으며, 다음 목표가 가로등·표지판·건물 실루엣·밝은 나무 등 최소 하나로 읽히는지 확인한다.
- 12m 밖의 나무가 지나치게 선명하게 반복되거나, 45m 밖이 텅 빈 배경으로 보이지 않는지 확인한다.
- 이동 가능한 경계가 보이지 않는 충돌벽에 막히지 않는지 확인한다. 막는 이유는 경사·펜스·바위·나무 등 화면 안에서 납득되어야 한다.
- 320×240 목표 렌더에서 나무, 시설물, 길, 원경의 명도 그룹이 서로 섞이지 않는지 확인한다.
- Game 뷰와 Profiler에서 나무·풀 밀도를 단계적으로 올리며 프레임 시간, 드로우콜, 그림자 비용을 기록한다.

- 사용자 결정(2026-09-12)
  - 숲을 풍성하게 하려고 잎 달린 나무를 추가했다. 4.2장의 "잎이 무성한 건강한 숲은 1차 범위에서 만들지 않는다"를 대신한다. 배치에서는 죽은 나무와 섞고, 약 60%를 잎 나무로 둔다.
  - LOD는 적용하지 않는다. 로우폴리라 필요 없어서, 7장 표는 참고용으로만 남긴다.
- 기타: `ChoirTotem_A`(비주얼 컨셉의 얼굴 합창)
- 지형: Unity Terrain 대신 Blender 로우폴리 메시로 만들었다(사용자 결정). 크기는 128×128m, 격자는 2m이다. 3.1장 레이어 4종은 `T_Forest_Ground_Atlas`의 타일로 칸마다 칠하고, 길은 컷아웃 띠로 얹는다. 그래서 Terrain Paint Trees/Details 대신 배치 스크립트가 흩뿌린다.
- 원경: 2장의 원경 계층(45m 이상)에 산자락과 산맥 링(반경 780m, 북쪽 연구소 뒤가 가장 높음)을 더했다. 이 링이 지형 끝에서 하늘이 바로 보이던 문제를 막는다. 연구소 외벽은 북쪽 언덕에 파묻힌 옹벽이 되었다(사용자 요청, 2026-09-12).
