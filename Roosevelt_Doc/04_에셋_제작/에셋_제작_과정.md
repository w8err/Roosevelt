# 에셋 제작 과정 (지하 연구소 모듈)

갱신 2026-09-12. 무엇을 만드는지는 `에셋_규격서_지하연구소.md`, 이 문서는 어떻게 만드는지를 다룬다.

## 흐름
1. 규격서에서 크기, 삼각형 예산, 아틀라스 빈 영역을 확인한다
2. Blender 스크립트로 모듈을 만든다 (`Art/tools/`)
3. 검수 방에 조립해 겹침 검사와 카메라 렌더를 한다
4. FBX, 아틀라스, 배치 JSON을 Unity로 익스포트한다
5. Unity에서 씬을 빌드하고 캡처로 확인한 뒤, Play로 걸어 본다
6. 규격서 표를 갱신하고 커밋한다

## 1. 모델링
- 모듈 원본은 백그라운드 Blender로 고친다. MCP로 연결된 Blender는 검수·배치 전용이다.
  ```
  blender.exe -b "Art/Lab/Lab_Modules.blend" --python-exit-code 1 -P "Art/tools/make_xxx.py"
  ```
  Blender 경로: `D:\01_Programs\Steam\steamapps\common\Blender\blender.exe`
- 고치기 전에 원본을 `Lab_Modules.backup-before-<작업>.blend`로 복사한다.
- 새 모듈은 `make_doors.py`, 기존 모듈을 조금 바꾼 변형은 `make_doorpair.py`를 본뜬다.
  - `add_box`에 필요한 면만 넘긴다. 다른 형상에 붙어 가려지는 면을 빼면 삼각형이 줄고 깜빡임도 막는다
  - UV는 면마다 준다. 큰 면은 `planar_uv(영역)`(64px/m), 작은 부품은 `planar_uv(영역, fit=True)`, 옆면은 `solid_uv(x, y)`(한 픽셀 색)
  - 정점을 옮겨 변형을 만들 때는 옮긴 모서리의 UV를 같은 비율로 보간해 텍스처 크기를 지킨다
  - 기존 모듈에서 파생할 때는 `fit_existing_uv`로 원본 면의 UV 규칙을 역산해 새 면에 그대로 쓴다 (문틀 벽이 이렇게 만들어짐)
  - 새 오브젝트는 `ensure_collection('Lab_Modules')`에 넣고 `place_after_others`로 줄 세운다
  - 같은 이름이 이미 있으면 멈추게 하고, 끝에서 `tri_count`와 `zfight_pairs([ob])`를 출력한다
- 원점과 방향은 규격서 2장을 따른다. 벽은 앞면 왼쪽 아래, 문짝은 닫힌 상태의 바닥 중앙이다.
- 둥근 소품(나무, 토템)은 `add_tube`(경로를 따라 다각형 단면을 쓸기, 몸통·목·뿌리), `add_ring`(원판·원뿔·부채꼴), `matrix`를 준 `add_box`(기울어진 가면·손)로 만든다. 숲 소품 원본은 `Art/Forest/Forest_Props.blend`, 예시는 `make_choir_totem.py`, 검수 렌더는 `review_totem.py`처럼 원본을 저장하지 않고 백그라운드에서 뽑는다.
- `zfight_pairs`는 같은 평면의 면끼리 실제 다각형 교차 면적을 계산한다. 모서리만 맞닿은 면은 겹침으로 치지 않는다.

## 2. 아틀라스
- `T_Lab_Atlas` 512px 한 장. 빈 영역 색은 #2e4d46.
- 칠하기 전에 `Atlas.is_free`로 영역이 비었는지 확인하고, 비어 있지 않으면 멈춘다.
- 팔레트 5색(`TEAL MINT YELLOW PEACH RED`)에서 `mul`/`mix`로 명암만 파생한다. 픽셀 노이즈를 조금 넣어 기존 질감과 맞춘다.
- 깔끔·더러운 변형은 기존 영역을 복사한 뒤 얼룩 픽셀만 같은 영역의 깨끗한 픽셀로 바꾼다 (`archive/2026-09-12_make_variants.py`).
- `Atlas.commit(미리보기 경로)`로 이미지를 다시 팩하고, 미리보기 PNG를 눈으로 확인한다.
- 새 영역은 규격서 3장 표에 적는다.

## 3. 검수와 배치
- `Lab_TestRoom.blend`를 연 Blender에서 `lib.reload()`로 원본을 다시 읽고, 새 메시를 링크한다.
- 배치마다 컬렉션을 하나 쓰고, 렌더할 때는 다른 배치 컬렉션을 뷰 레이어에서 뺀다 (같은 좌표에 겹쳐 있음).
- 방은 6×6m. 벽 회전은 북 0°, 남 180°, 서 90°, 동 -90°. 벽 왼쪽 끝이 닿는 안쪽 모서리에는 `CornerIn`을 쓴다.
- 방을 이을 때는 벽을 두 겹으로 등을 맞댄다 (두 벽의 뒷면이 한 평면, 다음 방은 0.4m 뒤에서 시작). 연결 문은 한쪽 `Door`, 반대편 `DoorPair`이고 문짝은 `Door` 쪽에만 단다.
- 문짝은 문 벽 좌표 (1.0, 0.1, 0)에 벽과 같은 회전으로 놓는다. 상태등과 키패드는 벽과 같은 위치·회전.
- 배치 전체 `zfight_pairs`가 0인지 확인한다.
- `bpy.ops.render.render`로 카메라 렌더를 파일로 뽑아 이음새, 반복 무늬, 색을 본다. 문 구멍 안쪽처럼 가려진 곳은 문짝을 `hide_render`로 숨기고 찍는다. 뷰포트 스크린샷은 갱신이 늦을 때가 있다.
- 저장·익스포트 전에 씬 오브젝트 목록을 확인한다. Blender 하나를 여러 Claude 세션이 같이 쓴다.

## 4. 익스포트
- `labkit.export_mesh_fbx(메시, 경로)`: 원점에 놓은 오브젝트 하나로 FBX를 만든다 (Forward -Z, Up Y, Apply Transform, 스케일 1).
- 아틀라스는 팩된 PNG 바이트를 그대로 쓴다. 색 변환이 없다.
- 배치 JSON(`Layouts/<이름>.json`, 좌표는 전부 Blender 기준):
  - `scene`: 만들 씬 이름 (없으면 파일 이름)
  - `material`, `atlas`, `prefabDir`: 키트별 머티리얼·아틀라스·프리팹 폴더 (없으면 연구소 값). 메시는 배치 파일이 있는 키트의 `Meshes/`에서 찾는다
  - `ground`, `environment`: 야외 배치용 바닥 크기·색, 안개(`fogMode` 등)·주변광·하늘색·해 방향(Blender 좌표). `fogMode`가 비어 있으면 실내 기본값
  - `modules`: 고정 모듈 `{mesh, pos, rotZ}`. 벽에 붙는 상태등·키패드도 여기
  - `doors`: `{leaf, parts, pos, rotZ, locked}`. `parts`는 문짝과 함께 도는 손잡이·잠금 바
  - `lights`: 조명 천장 위치에서 계산한 포인트 라이트
  - `camera`: 캡처용 카메라 `{pos, target, fov}`
  - `playerStarts`: 플레이어 시작 지점 `{pos, target}` (선택)
- 이름을 바꿀 때는 `.fbx`와 `.fbx.meta`를 함께 옮겨 GUID를 지킨다.
- FBX 안의 노드 이름은 `<메시 이름>.001`이다(원본 오브젝트가 이름을 쥐고 있어서 `export_mesh_fbx`의 임시 오브젝트에 접미사가 붙는다). Unity는 이걸 파일 이름의 루트 + `.001` 자식으로 임포트하고, 축 변환이 자식에 걸릴 수 있다. 그래서 움직이는 부품(다이얼·레버·바늘·버튼·문짝)을 코드로 돌릴 때는 **반드시 프리팹 루트**를 대상으로 하고, 이름으로 자식을 찾지 않는다. 원점=회전축 계약은 루트 기준이다(2026-09-24 LabPanel 바늘이 엉뚱한 점을 중심으로 돈 원인)

## 5. Unity
- `Assets/Art/` 아래 텍스처는 임포트할 때 Point 필터, 밉맵 끔, 무압축이 자동으로 걸린다.
- 씬 빌드는 메뉴 `Roosevelt > Lab > Build Layouts`, 또는 `Temp/LabSceneBuilder.request` 파일을 만들면 된다 (에디터가 1초마다 확인). 배치 파일마다 씬을 하나씩 만들고, 가장 최근에 익스포트한 배치의 씬을 열어 둔다. 열린 씬에 저장 안 된 변경이 있으면 건너뛴다.
- 빌드는 창이 뒤에 있어도 돈다. 빌더가 먼저 에셋을 새로고침한다. 새 스크립트는 창에 포커스가 가야 컴파일된다.
- 결과
  - 프리팹 `PF_Lab_*`: 문 벽(`Door`, `DoorPair`)은 MeshCollider, 문 부품은 충돌체 없음, 나머지는 BoxCollider
  - 문: `Door_<종류>/Hinge(LabDoor)/문짝·손잡이`. 경첩은 문짝의 경첩 쪽 앞면 모서리, 앞쪽(방 쪽)으로 90° 열린다. `locked`면 안 열린다
  - 플레이어: `PF_Player` = CharacterController + `FirstPersonController`(이동, 시점, E) + `PlayerCameraFeel`(서 있을 때와 걸을 때의 노이즈 섞기). 자식은 `CameraTarget`(눈 높이 1.6m, 상하 시점), `PlayerCamera`(시네머신 카메라: 위치 고정, 회전 따라가기, `Noise_WalkBob` 노이즈, 연출용 임펄스 리스너), `MainCamera`(브레인). 처음 한 번만 만들고 이후 수정은 유지된다 (시네머신 이전 구조일 때만 같은 GUID로 다시 만든다)
  - 캡처 `Logs/<씬 이름>.png`
- Play 조작: WASD 이동, 마우스 시점, E로 문 여닫기 (패드는 왼쪽 스틱, 오른쪽 스틱, 위쪽 버튼).
- 로그는 프로젝트의 `Logs/Editor.log`. `[LabSceneBuilder]`, `[LabDoor]`로 찾는다.
- 좌표 변환: Blender (x, y, z) → Unity (-x, z, -y), Z회전 θ → Y회전 -θ.

## 5.1 야외 숲
- 소품 원본은 `Art/Forest/Forest_Props.blend`(컬렉션 `Forest_Props`)이다.
  - 만드는 스크립트: `make_choir_totem.py`, `make_forest_vegetation.py`, `make_forest_facility.py`, `make_forest_foliage.py`(잎 나무·풀·뿌리·잎 원경), `make_forest_equipment.py`(출입문·발전기)
  - 검수 렌더는 `review_forest.py`로 뽑는다. 결과는 `Art/Forest/review/forest_*.png`에 저장된다.
- 아틀라스는 네 장이다. 모두 512px이고, 알파 있는 두 장은 컷아웃 머티리얼로 그린다.
  - `T_Forest_Bark_Atlas`: 나무
  - `T_Forest_Props_Atlas`: 바위·시설·설비
  - `T_Forest_Cutout_Atlas`: 수풀·원경·철망(알파 있음)
  - `T_Forest_Foliage_Atlas`: 잎·풀·잎 원경(알파 있음)
- 잎은 가지 끝마다 잎 뭉치 하나를 단다(`leaf_cluster`). 뭉치는 서로 직각인 세로 카드 두 장과 누운 카드 한 장으로 되어 있다.
- `make_forest_test.py`는 `Art/Forest/Forest_Test.blend`를 매번 새로 만든다. 그러니 이 파일은 손으로 고치지 않고 스크립트를 고친다.
  ```
  blender.exe -b --factory-startup --python-exit-code 1 -P "Art/tools/make_forest_test.py"
  ```
  - 지형: 128×128m, 2m 격자. 칸마다 바닥 타일 하나(`T_Forest_Ground_Atlas`, 128px = 2m)를 쓴다.
  - 길: 지형 위 4cm에 띄운 컷아웃 띠
  - 북쪽 언덕(`north_hill`): 외벽 바로 뒤와 양 끝에서 땅이 벽보다 높이 솟는다. 그래서 연구소 입구가 산에 파묻힌 모습이 된다.
  - 산자락·산맥(`SM_Forest_Horizon_Test`): 지형 가장자리 꼭짓점에서 시작하는 링을 반경 780m까지 잇는다.
    - 125m 안쪽은 `M_Forest_Ground`를 쓴다(씬 안개 적용).
    - 바깥 산은 `M_Forest_Haze`를 쓴다. 셰이더 `Roosevelt/Distant Haze`는 씬 안개 대신 높이로 안개색을 섞는다. 30m 아래는 완전히 안개색이고 150m에서 70%까지 드러난다.
    - 산 링은 꼭짓점을 4개 중 하나만 쓴다. 가늘고 긴 삼각형은 줄무늬처럼 보이기 때문이다.
  - 배치는 스크립트가 정한다. 시설, 공터, 기형 나무는 좌표를 직접 주고, 나무·바위·수풀은 흩뿌린다.
  - 한 번 실행하면 소품 전부, 지형, 길의 FBX, 아틀라스 네 장, `Layouts/Forest_Test.json`을 Unity로 내보낸다. 검수 렌더는 `Art/Forest/review/Forest_Test_*.png`에 저장된다.
- 배치 JSON에 두 필드가 추가됐다.
  - `materials`: `{name, atlas, cutout}`. FBX 머티리얼 슬롯 이름으로 머티리얼을 찾고, 목록에 없는 슬롯은 `material`을 쓴다. 컷아웃 머티리얼은 알파 클립을 켜고 양면으로 그린다.
  - `modules[].scale`: 균일 크기. 0이면 1로 친다.
- 충돌체는 빌더의 이름 태그 목록으로 정한다.
  - MeshCollider: `_Terrain_`, `_Tree_`, `_ChoirTotem_`, `_Rock_`, `_Log_`, `_Stump_`, `_Wall_Door`
  - 충돌체 없음: `_Shrub_`, `_Backdrop_`, `_Path_`, `_WarningLight_`, `_CCTV_`, `_DoorPart_`
  - 나머지: BoxCollider

## 6. 체크리스트

- [ ] UV가 비어 있던 아틀라스 영역 안에 있다
- [ ] 모듈 단독과 배치 모두 겹침 0
- [ ] Blender 검수 렌더 확인
- [ ] Unity 캡처 확인, 로그에 에러 없음
- [ ] 규격서 3장 표와 7장 목록 갱신

## 7. 자주 걸린 문제
| 증상 | 원인 | 해결 |
|---|---|---|
| 카메라를 돌리면 표면이 반짝임 | Point 필터 + 작은 텍스처 | 의도된 스타일 |
| 방 모서리 몰딩이 깜빡임 | 두 벽의 몰딩이 2×2cm 겹침 | `CornerIn` 사용 |
| 이어 붙인 방의 문 구멍 안이 깜빡임 | 등을 맞댄 두 `Door` 벽의 문틀이 겹침 | 반대편은 `DoorPair` |
| 새 오브젝트가 저장 후 사라짐 | 컬렉션에 넣지 않음 | `ensure_collection` |
| 파일에 모르는 오브젝트가 섞임 | 다른 세션이 같은 Blender를 씀 | 저장 전 목록 확인, 원본은 백그라운드로 |
| 빌더를 눌러도 결과 없음 | 씬 저장 창 취소, 컴파일 중 클릭 | 먼저 Ctrl+S, 요청 파일 방식 사용 |
| 빌드가 옛 배치로 됨 | 새 빌더 스크립트가 아직 컴파일 전 | Unity 창에 한 번 포커스 |
| 로그에 아무것도 안 찍힘 | 옛 로그(`%LOCALAPPDATA%`)를 봄 | `Logs/Editor.log` |
